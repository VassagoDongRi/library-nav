# 书架 · 设计规划

这份文档回答「为什么这样排」和「以后怎么长」，代码细节看 README，字段看 DATA.md。

---

## 1. 定位

| | 导航站 nav.dongri.work | 资料站（本仓库） |
| --- | --- | --- |
| 用户动作 | 找入口、找网站 | 找一份具体文件 |
| 组织单位 | 分类 → 网站卡片 | 学段 → 学科 → 类型 → 文件 |
| 判断依据 | 站点名 + 一句描述 | 格式、体量、更新时间、标签 |
| 更新频率 | 偶尔加链接 | 跟着学期持续加文件 |

所以不做「第二个导航站」，也不做网盘式的文件树。目标是：**进来三秒内判断这份文件要不要打开。**

---

## 2. 信息架构

```text
学段（大学 / 高中 / 以后的研究生…）
└─ 学科（高等数学 / 线性代数 / 程序设计 / 大学英语 / 习思想…）
   └─ 类型（教材 / 习题 / 笔记 / 论文试卷）
      └─ 文件（PDF / HTML / DOCX / MD…）
```

- **学段**是最高层，因为它决定「你是谁」：大学和高中不会混着看。
- **学科**承担颜色和分组，是扫读的主线索，所以每组一个颜色、卡片一条 3px 色条。
- **类型**是筛选维度，也是文件夹的第二层，和 `resource/` 完全对齐。
- **文件**不建树状导航，用卡片承载。

物理目录 `resource/<学段>/<类型>/<学科>/` 和展示层级（学段/学科/类型）不完全同序，
这是故意的：文件夹按「我拿到一批教材」来放最顺手，页面按「我要找高数」来排最顺手。
JSON 承担这层映射，两边都不用迁就对方。

**为什么不用侧边栏目录树**：树适合「我知道我要什么」，资料库更多是「我看看有什么」。
横向分组 + 颜色 + 最近更新，比点开三层目录更快；搜索又兜住了「我知道我要什么」的情况。

## 3. 首页分区

```text
┌──────────────────────────────────────────┐
│ 顶栏  书架 · 全部/大学/高中 · 主题切换    │ 56px 吸顶
├──────────────────────────────────────────┤
│  Hero：小字眉标 + 一句话标题 + 搜索框      │ 留白 ~80px
│        [全部][教材][习题][笔记][论文试卷]  │
│        全部学段 · 5 个学科 · 17 份资料     │
├──────────────────────────────────────────┤
│ 最近更新  横向 6 张（回访第一眼）          │
├──────────────────────────────────────────┤
│ 高等数学 ● 4                               │
│   教材  2  ┌卡┐┌卡┐                       │
│   习题  1  ┌卡┐                           │
│   笔记  1  ┌卡┐                           │
├──────────────────────────────────────────┤
│ 线性代数 ● 3 …（下一组）                   │
└──────────────────────────────────────────┘
```

三条排版规则：

1. **节奏是「大—小—中」**：Hero 只有一句话和一个搜索框，留白足够；
   「最近更新」是横滑过渡；下面是密度更高的卡片网格。全是同密度卡片会像表格。
2. **一张卡只承载三件事**：标题、一句描述、底部元信息（体量 + 日期）。
   不塞标签云、不塞按钮、不塞封面——封面会让卡片高度参差，破坏扫读节奏。
3. **分组不超过 6 个**：学科多于 6 个时，合并相近课程（例如「数学」下挂高数/线代/概率），
   否则首页会变成无限长列表。类型筛选放在 Hero，不额外占分组位。

## 4. 视觉规范

| 项 | 值 | 说明 |
| --- | --- | --- |
| 主色 | 墨绿 `#1f6f5c` | 和导航站的紫蓝渐变区分开，更「学术」 |
| 底色 | 纸白 `#f6f4ef` | 不用纯白，长时间不刺眼 |
| 卡片 | `#fffefb` + 1px 描边 | 靠描边分层，不靠阴影堆叠 |
| 强调 | 琥珀 `#b08347` | 只用于置顶、示例提示这类小面积 |
| 标题字 | Noto Serif SC / 宋体 | 衬线是「教材感」的来源 |
| 正文字 | 系统无衬线 | 阅读效率 |
| 字号阶梯 | 44 / 19 / 16.5 / 15 / 13 / 12 / 11 | 七级，够用且不膨胀 |
| 圆角 | 卡片 14px，按钮/徽章 999px | 大圆角按钮 + 中圆角卡片，拉开层次 |
| 间距 | 8 的倍数 | 组内 8~12，组间 48~52 |
| 学科色 | 每组一个色，卡片左侧 3px | 颜色即分组，不用重复写学科名 |

暗色模式：`html[data-theme="dark"]` 覆盖同一批变量；
用户没手动切换时走 `prefers-color-scheme`，系统变了页面跟着变。

## 5. 数据与渲染的分层

```text
data/index.json    站点信息 + 学段清单
data/types.json    类型注册表
data/college.json  学科 → 类型 → 条目
        │
        ▼
data.js    规整（补默认值、丢 draft、统一字段）
views.js   筛选（学段 → 类型 → 搜索词）+ 排序（置顶 → 日期 → 标题）
render.js  拼 HTML
search.js  建索引、打分
```

关键约定：

- **渲染器不认识具体学段名字**，只遍历 `index.json` 的 `stages`——所以新增学段是数据变更，不是代码变更。
- **未知字段一律忽略**，可以先加数据、后加展示。
- **某个学段 JSON 写坏不影响全局**，只有那一段显示「数据读取失败」。
- 所有用户数据都过 `esc()` 再进模板；颜色只接受 `#rgb/#rrggbb`。

## 6. 什么时候必须改代码

| 改动 | 是否要动代码 |
| --- | --- |
| 加文件/学科/类型/学段、改文案、改颜色 | 不用 |
| 卡片要多显示一个字段（作者、版本、页数…） | `render.js` 一处 |
| 新增一种排序（按体量、按字母） | `views.js` 的 `compareItems` |
| 新增独立路由（`/college/高等数学`） | 加一个极简 hash 路由，`app.js` 一处 |
| 接入全文检索（Pagefind） | 替换 `search.js` 的 `searchHits`，浮层不用动 |
| 换成 Vue/React | 不需要，除非站点规模超过几千条 + 需要复杂交互 |

## 7. 路线图

**v1（当前）**
- 学段切换、类型筛选、说明式空状态
- 卡片网格 + 最近更新横向区
- 搜索浮层：中文二元组分词、标题加权、↑↓/Enter/Esc
- 明暗主题、移动端适配、示例数据提示
- CI 校验 JSON 与文件路径

**v1.1 内容补全（只动数据）**
- 把 `data/college.json` 的示例条目换成真实文件
- `_demo` 改 `false`
- 高中开始整理时，填 `data/senior.json` 的 `items`

**v2 可选功能（按性价比排序）**
1. PDF 页内预览：卡片点击改成 `#page=1` 或浮层 `<iframe>`，成本低
2. 阅读进度：`localStorage` 记「打开过/看到第几页」，卡片上显示小进度条
3. 标签页：`tags` 已经有数据，加一个 `/tags` 视图
4. 全文搜索：笔记都变成 HTML 后接 Pagefind（只索引 HTML，PDF 仍需元信息搜索）
5. 贡献流程：用 Issue 模板收「缺哪份资料」，比开放 PR 更可控

## 8. 风险与注意事项

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 教材扫描件版权 | 公开仓库可能被投诉 | 只放可分享内容；大文件走网盘/Releases 外链 |
| 单文件 >100 MB | push 被拒 | 走 Releases 或对象存储，JSON 里写外链 `url` |
| 仓库/站点 >1 GB | Pages 发布失败 | 同上；定期清理重复文件 |
| 文件名大小写不一致 | 本地能开、线上 404 | CI 的 `check-data.mjs` 会检查（本机同样区分不了，只能靠脚本） |
| HTML/JSON 缓存 10 分钟 | 改完看不到更新 | 强制刷新；或 Pages 设置里确认没有自定义缓存头 |
| Git LFS | Pages 返回指针文件而不是 PDF | 不要用 LFS |
| 中文文件名 | 部分老工具编码错乱 | 浏览器与 Pages 都没问题；命令行操作时注意终端编码 |
